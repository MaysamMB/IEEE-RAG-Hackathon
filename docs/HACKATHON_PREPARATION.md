### 1.6 جلسة التحكيم [JG، ص 8]

- **10 دقائق لكل فريق: 5 عرض، 4 أسئلة، 1 انتقال.**
- اللجنة: محكّم تقني + محكّم أعمال وتسويق، ويُفضَّل ثالث من الصناعة. العلامة = متوسط المحكّمين.
- **اختبار مفاجئ:** المحكّمون يجهّزون مسبقاً **3 أسئلة** للمشكلة، **منها سؤال خارج النطاق**، ويطرحونها **مباشرة على نظامنا**.

## 3. ملخص معمارية RAG كما دُرِّست في البوتكامب

### 3.1 الفكرة [S1، ص 4–5؛ L4، ص 1–3]

نموذج اللغة الكبير (LLM) يعاني أربع مشكلات: **الهلوسة (Hallucination)**، **حد المعرفة (Knowledge Cutoff)**، **غياب المعرفة الخاصة (No Private Knowledge)**، **غياب المصادر (No Sources)** [S1، ص 4]. RAG = «امتحان بكتاب مفتوح» (Open Book) [S1، ص 5].

تحذير مهم: RAG **يقلّل** الهلوسة ولا يمنعها؛ قد تبقى الإجابة خاطئة إذا كان المستند ناقصاً أو استُرجع الجزء الخطأ أو أساء النموذج الفهم [L4، ص 3؛ S3، ص 11].

### 3.2 المرحلتان [S1، ص 7؛ L4، ص 4]

```
المرحلة الأولى — التجهيز (مرة واحدة / Indexing)
  المستندات → تنظيف → تقطيع (Chunking) → تضمين (Embeddings) → قاعدة متجهات (Vector DB)

المرحلة الثانية — لكل سؤال (Retrieval + Generation)
  السؤال → تضمين السؤال بنفس النموذج → بحث عن أقرب Top-k
         → دمج المقاطع مع السؤال (Augment) → LLM يولّد الإجابة → إجابة + مصادر
```

### 3.3 الخطوات الخمس بالكود [S2، ص 3–9؛ L5، ص 1–5]

| الخطوة | الدالة | ما تفعله | المرجع |
|---|---|---|---|
| 1. التحميل والتقطيع | `load_docs(folder)`، `chunk(text, size=500, overlap=100)` | قراءة ملفات `.txt` إلى قاموس، تقطيع بالأحرف مع تداخل | S2 ص 5؛ L5 ص 2–3 |
| 2. التضمين والتخزين | `chromadb.Client()`، `col.add(ids, documents, metadatas)` | Chroma يضمّن بنموذج مدمج صغير ويخزّن `source` | S2 ص 6؛ L5 ص 3–4 |
| 3. الاسترجاع | `retrieve(question, k=3)` | `col.query(query_texts, n_results=k)` | S2 ص 7؛ L5 ص 4 |
| 4. الإثراء (Augment) | `build_prompt(question, hits)` | «أجب فقط من السياق، وإن لم يوجد قل لا أعرف» | S2 ص 8؛ L5 ص 5 |
| 5. التوليد | `llm(prompt)`، `ask(question)` | استدعاء Claude عبر `anthropic`؛ المفتاح من متغير بيئة؛ `llm()` هي الدالة الوحيدة القابلة للتبديل | S2 ص 9؛ L5 ص 5 |

مثال التقطيع من [L5، ص 3]: نص 1200 حرف بحجم 500 وتداخل 100 ← 3 مقاطع: (0–500)، (400–900)، (800–1200).

### 3.4 التقييم والتحسين [S3، ص 4–8]

ثلاثة أسئلة تقييم [S3، ص 4]:
1. **استدعاء الاسترجاع (Retrieval Recall):** هل المقطع الصحيح ضمن Top-k؟
2. **الأمانة (Faithfulness):** هل الإجابة ضمن النص المسترجع؟
3. **فحص الرفض (Refusal):** هل يقول «لا أعرف» عندما يجب؟

أدوات البوتكامب: `retrieval_score(k)` بفحص كلمة مفتاحية [S3، ص 5]، `run_tests()` لفحص الإجابة [S3، ص 6]، جدول أعراض/أسباب/حلول [S3، ص 7]، حد المسافة [S3، ص 8].

أربعة أنواع أسئلة للاختبار [S2، ص 11]: حقيقة مباشرة، سؤال معاد صياغته، خارج المستندات، يحتاج مقطعين.

| حفظ رقم الصفحة في Metadata | البوتكامب يحفظ `source` فقط [S2، ص 6] |
| الجداول والنص العربي | غير مُغطّى |
| اختيار Embeddings مناسب للعربية | البوتكامب يستخدم «نموذجاً صغيراً مدمجاً» في Chroma [S2، ص 6] دون نقاش للعربية |
| Hybrid / Reranking / تصفية Metadata | غير مُغطّى |
| Precision@k | غير مُغطّى (البوتكامب يغطي Recall بالكلمة المفتاحية فقط) |
| اللهجة المحكية، PDF ممسوح، مصادر متعارضة، محادثة متعددة الأدوار | مذكورة كتحديات [JG، ص 11] وغير مُغطّاة |

**الخلاصة:** كود البوتكامب يحقق «خط الأساس»، لكنه **وحده لا يكفي** لنيل علامة عالية في المعيار 1.

### 7.2 مسار البيانات

```
[PDF/TXT] → ingest (صفحة بصفحة) → preprocess → chunking
     → metadata: {source, page, section, version, date, chunk_id}
     → embeddings → ChromaDB (persistent)

[سؤال] → (rewrite: لهجة/متابعة) → embed → retrieve top-k
     → فلتر metadata → بوابة المسافة ── لا شيء قريب → «لا أعرف» (دون استدعاء LLM)
     → (optional rerank) → prompt مع وسوم [مصدر، صفحة]
     → Claude → إجابة + citations → تحقق أن كل citation موجود فعلاً ضمن المقاطع المسترجعة
```

### 7.4 خطة التقييم (🟦 توصية مبنية على الحد الأدنى الرسمي)

| الفئة | العدد المقترح | ما يختبره |
|---|---|---|
| مباشر | 3 | الاسترجاع الأساسي + Citation |
| معاد الصياغة | 2 | البحث بالمعنى [S2، ص 11] |
| متعدد المقاطع/المستندات | 2 | Top-k والدمج |
| لهجة محكية | 2 | تحدي اللهجة |
| تعارض/إصدار قديم | 1 | التعامل مع التعارض |
| خارج النطاق | 2 | الرفض |
| **المجموع** | **12** | (≥ 10 المطلوبة رسمياً) |

**المقاييس:**
- **Precision@k** = عدد المقاطع ذات الصلة ضمن Top-k ÷ k.
- **Recall@k** = هل المقطع/المقاطع المرجعية ضمن Top-k.
- **Faithfulness** = هل كل جملة في الإجابة مدعومة بالمقاطع (مراجعة يدوية على 10–12 سؤالاً ممكنة في الوقت المتاح).
- **دقة الاستشهاد (Citation Accuracy)** = هل المصدر/الصفحة المذكوران صحيحان.
- **دقة الرفض** = رفض الأسئلة خارج النطاق **وعدم** رفض الأسئلة التي لها إجابة.

⚠️ لا تُكتب أي نتيجة إلا بعد تشغيلها فعلياً.

## 9. دليل دراسة أسئلة التحكيم

> الأسئلة العشرة الأولى **رسمية** من بنك أسئلة المحكّمين [JG، ص 8]. الإجابات 🟦 **نماذج إرشادية** يجب استبدال أجزائها بين [أقواس] بأرقامنا الفعلية.

### 9.1 بنك الأسئلة الرسمي

**س1: لماذا اخترتم هذه الاستراتيجية في التقطيع؟ وماذا يحدث لو غيّرتم الحجم أو التداخل؟**
- النقاط: قطّعنا بحسب الفقرات لأن الفقرة وحدة معنى؛ التداخل يمنع ضياع جملة عند الحد [S2، ص 5]. المقاطع الكبيرة تُدخل ضجيجاً، والصغيرة تفقد السياق [S3، ص 7].
- الدليل: «جرّبنا [X] و[Y] وكان Recall@k [قبل] ← [بعد]».

**س2: أي نموذج Embeddings استخدمتم ولماذا؟ وكيف يتعامل مع العربية؟**
- النقاط: النموذج متعدد اللغات؛ قارنّاه مع [بدائل] على [N] سؤالاً عربياً؛ النتيجة [أرقام].
- تجنّب: «اخترناه لأنه مشهور» — المحكّم يريد دليلاً.

**س3: ماذا يفعل النظام إذا سألناه عن شيء غير موجود؟ (اختبار مباشر)**
- النقاط: طبقتان — بوابة مسافة مُعايرة من بيانات التقييم [S3، ص 8]، ثم Prompt يمنع الإجابة خارج السياق [S2، ص 8]. دقة الرفض في تقييمنا [X/Y].
- **جهّز:** جرّب أمام المحكّم مباشرة بثقة.

**س4: كيف قستم جودة النظام؟ وما أسوأ سؤال فشل فيه ولماذا؟**
- النقاط: [N] سؤالاً في [فئات]، Precision@k و Recall@k ودقة الرفض والاستشهاد. **احفظوا مثال فشل حقيقي** مع سببه وما فعلناه.
- هذا البند معيار كسر التعادل الثاني [JG، ص 6].

**س5: كيف يتعامل النظام مع معلومات متعارضة أو قديمة؟**
- النقاط: نخزن `version`/`date`؛ الـ Prompt يطلب ذكر التعارض مع المصدرين والإشارة للأحدث. حد أساسي: النظام يعرف فقط ما في الملفات [S3، ص 11].

**س6: كم تكلف الإجابة الواحدة؟ وكيف تتغير عند 10,000 مستخدم؟**
- النقاط: متوسط tokens المُسجّل [X input + Y output] × سعر النموذج = [تكلفة]. الـ Embeddings محلية (تكلفة صفرية لكل طلب). الأسئلة المرفوضة بالبوابة لا تستدعي LLM. ⚠️ الأسعار **يجب** أخذها من صفحة الأسعار الرسمية يوم المسابقة وذكر المصدر.

**س7: من أين جاءت أرقام السوق؟ وما أضعف افتراض في خطتكم المالية؟**
- النقاط: كل رقم مع مصدره في الشريحة؛ نعرف أضعف افتراض ونقوله بصراحة (مثلاً معدل التحويل). الصدق هنا يكسب؛ الأرقام المختلقة تُخصم [JG، ص 6].

**س8: ما الذي كتبتموه بأنفسكم وما الذي ولّده الذكاء الاصطناعي؟ اشرحوا هذا الجزء من الكود.**
- النقاط: إجابة صادقة مطابقة لإفصاح README. **كل عضو** يستطيع شرح `retrieve()` و`build_prompt()` و`ask()` سطراً سطراً [L5 مرجع جيد للمراجعة].

**س9: كيف تحمون خصوصية البيانات الحساسة؟**
- النقاط: المفاتيح في env فقط؛ `.env` و `data/raw` خارج Git؛ Embeddings محلية فلا يغادر النص كاملاً إلا المقاطع المسترجعة إلى LLM؛ لا نرسل ملفات خاصة لنموذج مستضاف دون إذن [S3، ص 11]. خطة: نشر محلي أو نموذج محلي للعملاء الحساسين (`llm()` قابلة للتبديل [S2، ص 9]).

**س10: من أول ثلاثة عملاء ستتواصلون معهم بعد المسابقة وماذا ستقولون لهم؟**
- النقاط: ثلاث جهات **مسمّاة** ومحددة حسب المشكلة + رسالة من جملة واحدة + ما سنطلبه منهم (تجربة مجانية؟ بيانات؟).

### 9.2 أسئلة إضافية متوقعة (🟦 مستنتجة من بنود التقييم)

| السؤال | البند الذي يختبره | نقاط الإجابة |
|---|---|---|
| لماذا RAG وليس ChatGPT وحده؟ | مبرر RAG [JG ص 3] | المشكلات الأربع: الهلوسة، حد المعرفة، لا معرفة خاصة، لا مصادر [S1 ص 4] + التحديث دون إعادة تدريب [L4 ص 5] |
| لماذا RAG وليس بحثاً نصياً عادياً؟ | مبرر RAG | البحث بالمعنى («Money back» يجد «refund policy») [S1 ص 10] + إجابة مصاغة مع مصدر |
| هل RAG يمنع الهلوسة؟ | التأريض | لا، يقللها فقط [L4 ص 3؛ S3 ص 11] — ولهذا لدينا رفض وتقييم Faithfulness |
| لماذا k = [قيمتنا]؟ | Top-k [JG ص 3] | k صغير قد يفوّت الإجابة، كبير يضيف ضجيجاً [S1 ص 10]؛ اخترناه من مقارنة k=1/3/5 [أرقام] |
| ما Top-k وما المسافة (distance)؟ | الاسترجاع | k عدد المقاطع؛ المسافة أصغر = أقرب [S3 ص 8] |
| كيف اخترتم حد الرفض؟ | الرفض | طبعنا المسافات لأسئلة جيدة وخارج النطاق واخترنا قيمة بينهما [S3 ص 8] |
| ماذا لو كانت الوثيقة PDF ممسوحة؟ | الاستيعاب | [ما بنيناه فعلاً: كشف + تحذير / OCR] |
| كيف يتوسع النظام لـ 1000 مستند؟ | التوسع [JG ص 4] | الفهرسة مرة واحدة، قاعدة دائمة، إضافة تزايدية، التكلفة لكل سؤال لا تتغير بعدد المستندات تقريباً بل بـ k وطول المقاطع |
| ما الفرق بين Embeddings والتمثيل الثنائي؟ | فهم أساسي | الـ Embeddings تمثيل رقمي للمعنى وليس مجرد Binary [L4 ص 4] |
| ما الذي يجعل منتجكم مختلفاً عن المنافسين؟ | الشريحة 8 [JG ص 7] | العربية/اللهجة + المصدر في كل إجابة + السياق المحلي |
| من يدفع؟ ولماذا يدفع؟ | الإيرادات [JG ص 4] | جهة محددة + الألم الذي توفره بالأرقام (افتراض معلن) |
| ما خطتكم لأول 90 يوماً؟ | التسويق [JG ص 4] | 3 مراحل × 30 يوماً بمؤشرات رقمية |

### 9.3 قواعد ذهبية للإجابة
